* Code as Documentation: Self-Documenting Code Reviewer

** Goal
Add guidance to the code author flow and a dedicated code reviewer role
that validates code is self-documenting — not through comments, but
through naming, structure, and object design.

Guiding principle (Mokevnin's Mental Programming): good code encodes
the domain's mental model. The goal is "code that transfers
understanding," not just "code that doesn't need comments."

** Constraints
- ~40 lines of additions across 3 files — no structural flow changes
- Code Clarity Reviewer is implementation-phase only (no design-phase)
- Checklist in CODE-QUALITY.md (single source), referenced from flows
- No new tooling — Claude IS the reviewer
