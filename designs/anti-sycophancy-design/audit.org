* Root Pattern

All gaps follow the same structure: validation is internal (does
user's answer self-contradict?) but not external (does it contradict
project constraints, original intent, or actual system state?).

* Gap Summary

| Scenario | User Input | Current Check | Gap | Severity |
|----------|-----------|---------------|-----|----------|
| A: Answer processing (5a) | answers.org | Internal consistency | Not checked against Constraints/AC | High |
| B: Review loop (13) | review-notes.org | Matches design | Not checked against intake | High |
| C: Steering messages | Chat mid-flow | None — "incorporate" | Bypasses all gates | Critical |
| D: Steward scope | Steering log | Design vs intake | Doesn't flag user self-contradiction | High |
| E: Pattern capture (13d) | Corrections | Frequency/recurrence | Correctness not validated | High |
| F: Context maintenance | CLAUDE.md updates | None | Not checked against codebase reality | Medium |

* Key Insight

Steering messages (Scenario C) are the most dangerous — they bypass
ALL reality-check gates. The flow says "acknowledge briefly and
incorporate" with zero validation against Original Prompt, Goal, or
Constraints. This is the primary sycophancy vector.

* Recommended Remedies

1. Steering pre-validation: check against Original Prompt before incorporating
2. Steward self-contradiction check: flag when Steering contradicts Original Prompt
3. Answer constraint validation: Validator checks against Constraints/AC
4. Review-time constraint validation: Fix Validator checks against intake
5. Pattern correctness validation: require evidence before capturing as convention
6. Context reality-check: validate CLAUDE.md updates against codebase
